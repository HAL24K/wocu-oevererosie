# VVR lens — how well do we predict the regions that matter? (2026-09-07)

Luke's advice (7 Sep): improve the model *for the regions that have a VVR*.
This note applies that lens to run `20260907-near-fz` (`scripts/vvr_lens.py`).
Region ↔ VVR mapping is spatial: a scope region counts as a VVR region when it
intersects a VVR polygon (`Vlak_vrije_ruimte_natuurvriendelijke_oever_pl`).
1,447 of 12,130 scope regions do; 1,020 of the 5,750 modelled regions (18 %).

## 1 · VVR regions are easier — and the model adds less there

| | VVR regions | no VVR | all |
|---|---|---|---|
| modelled regions | 1,020 | 4,730 | 5,750 |
| 1-yr CV error, mean / median | 2.14 / 0.98 | 2.62 / 1.05 | 2.54 / 1.04 |
| share > 2 m/yr / > 5 m/yr | 30 % / 10 % | 31 % / 13 % | 31 % / 12 % |
| horizon error (segment), mean | 0.79 | 0.78 | 0.78 |
| SAM-preferred | 78 % | 74 % | 75 % |
| region model, own test split: MAE / naïve / **skill** | 1.60 / 1.70 / **+6 %** | 2.64 / 2.97 / +11 % | 2.45 / 2.74 / +11 % |

Absolute errors are *lower* on VVR regions (calmer banks), but so is the
naïve baseline — and the model beats "keep the historical average" by only
6 % there, against 11 % elsewhere. For the regions Luke cares about, the
model is currently barely better than the trend line. That is the honest
headline for Wednesday.

## 2 · The worst VVR regions are a different population

- Of the general worst-100, only **18** have a VVR.
- Worst-100 among VVR regions (overall ranks #8–#529): **95 SAM-preferred, 76
  without any cleaning flag**, horizon errors 12.4 → 1.3 m/yr (far below the
  general worst-100's 28.8 → 3.5). Rivers: **maas3 85**, ijssel1 6,
  nederrijn 5, maas2 4.

So the VVR failures are not the spectacular data corruptions of the general
list — they are moderate errors, almost all on the Maas (maas3), almost all
SAM-preferred, almost all invisible to our filters. Pattern-hunting for the
VVR case should start on the Maas, not on the IJssel.

## 3 · VVRs predicted to cross soon — how much is data?

Export layer `vvr_rates_of_change`: 1,115 VVR polygons with a prediction; 91
predicted to cross by 2027, 139 by 2031, 193 by 2050. Cross-checked against
the host region's error (`vvr_kruising_check_20260907-near-fz.gpkg`):

- host region CV error > 5 m/yr: **19 of 91**; > 10 m/yr: **10**
- host region in the general worst-100: 4; host has a cleaning flag: 28;
  host SAM-preferred: 41; no modelled host region (inference-only): 8

Roughly a fifth of the "crossing by 2027" alerts sit on regions the model
demonstrably cannot predict — those are the alerts to distrust first. Caveat:
the spatial join attaches each VVR to the regions on *both* banks (≈ 6 per
VVR); the host-region attribution is loose until the segment-level crossing
logic exists.

## What follows

   report it next to the overall numbers from now on.
2. **Segment-level VVR crossing** ("any strip crosses the VVR"), which also

3. **Temporal-consistency rule, validated on VVR regions first** — 76 % of the
   worst VVR regions carry no flag.
4. **Maas3 deep-dive** with Etienne/Joost: 85 of the 100 worst VVR regions.
